# Navigation Guide

This page explains the main options in the OpsRadar sidebar and what each one is for.

## OpsRadar

### Workspaces

Use this to create and open workspaces that hold request data, event logs, and operational analysis for a specific team or process.

### Radar

Use this as the starting point for the product. It summarizes the current workflow state and points operators toward the most important areas.

### Request Catalog

Use this to start a structured internal request such as access, onboarding, Jira project creation, or review workflows.

### Approval Inbox

Use this to review incoming requests, approve them, reject them, or ask for more information.

### Alerts

Use this to track important operational notifications and follow-up items.

## Analysis

### Friction Dashboards

Use this to review request-level metrics such as stuck work, approval delays, and workflow debt.

### Workflow Benchmarks

Use this to compare workflows and see which paths are slower or more expensive than expected.

### Automation Initiatives

Use this to review which workflows are good candidates for automation or process improvement.

## Configure

### Intake Sources

Use this to control which systems can create OpsRadar requests, such as REST, CSV, Jira, Slack, or other configured sources.

### Workflow Templates

Use this to manage repeatable request patterns and the expected approval path for each one.

### Role Builder

Use this to define who can approve, fulfill, view, or manage different kinds of requests.

### Settings

Use this to manage identity, AI workspace settings, and operator diagnostics.

## Top-level controls

### Ask AI

Use this to ask an assistant about the current workspace or log without leaving the page.

### Sample Data

Use this to load sample data when you want to explore the product without wiring real systems.

### New Workspace

Use this to create a new workspace from scratch.

## Rule of thumb

If you are unsure where to start:

1. Use `Radar` for a quick status check.
2. Use `Request Catalog` to create work.
3. Use `Approval Inbox` to make decisions.
4. Use `Friction Dashboards` to see where work gets stuck.
